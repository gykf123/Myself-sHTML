视频转函数

纯前端 · 视频不上传

上传一段视频，走完整条链路：视频 → 图片组 → 函数组 → 图片组 → 视频。每一帧先采样成彩色网格，再变成一堆带颜色的函数（用 +0√(x−xmin)+0√(xmax−x) 锁住定义域），最后函数把帧画回来合成视频。也能把全部帧函数下载成 Txt，再导入本机重新合成，还能选择保留原视频音频。全程只在你的浏览器里跑，视频不会上传。

?5 · 常见问题

导出的视频没有声音？

转换设置里「保留原视频音频」默认是勾选的。如果结果说明写的是「无声」，通常是浏览器不支持录制音频轨（Safari 上常见）或自动播放被拦截，此时会退回无声输出。换 Chrome / Edge 再试一般就有声音。

支持哪些视频格式？

只要浏览器能解码就行：MP4（H.264）、WebM（VP8 / VP9）、MOV 通常都可以。HEVC / H.265 在部分浏览器里解不了，这类文件会直接提示加载失败。

导出的视频是什么格式？

优先 MP4（H.264 + AAC）；浏览器不支持时退回 WebM；两者都不支持（例如部分 Safari）就降级导出 PNG 序列，需要自己再合成视频。

怎么让还原出来的视频更清楚？

把「分辨率（每行像素数）」往右拉，或直接点档位：「清晰 80 / 高清 120 / 极致 160 / 天花板 200」，再配合颜色量化 6 级或 8 级，最下面还有「0 · 不量化」，颜色最真但函数条数会逼近上限，只建议在很小的图上试。分辨率越高，每帧函数条数成倍增长，转换和录制也会更久；超过 120 列会给出提醒，手机建议 80 以内。导出视频固定 1280×720，用了高质量缩放，色块边缘比早期版本干净很多。

为什么处理要等这么久？

因为要逐帧走完整条链路。帧数约等于视频时长乘以 FPS，20 秒 6 FPS 就是 120 帧，每一帧都要采样、生成函数、再画回来。想快就把 FPS 或分辨率调低。

「渲染后端」两个选项有什么区别？实测谁快？

GPU（默认）把一帧里几千条函数块打包成实例数据，一次 drawArraysInstanced 提交给显卡画完，不逐条走 Canvas 2D 的 fillRect。CPU 渡劫版是早期实现：一条函数一次 fillStyle + fillRect。两种后端画出来的像素完全一致（同一套坐标与取色，已逐像素比对过）。

但要说实话：在现在这条链路上，瓶颈根本不在「画」这一步。实测（160 列 / 90 行 / 2530 条函数）单帧渲染只有 0.1–0.5ms，而逐帧 seek 解码定位要 17ms 上下——渲染占比不到 3%。所以切到 GPU 后端体感提速有限，它解决的是「函数条数极多时不要把主线程压死」，不是「4 倍加速」。

真正快了一截的地方是每帧留档：改成直接写像素缓冲后，同样的 1px/格快照从 1.18ms 降到 0.09ms（约 13 倍），函数越多收益越大。结果区会实时列出采样 / 生成函数 / 渲染 / 留档各步的每帧耗时，自己看就知道时间花在哪。

设备不支持 WebGL2（老旧手机、禁用硬件加速、隐私模式）时 GPU 项会被置灰并自动留在 CPU 后端，功能不受影响。

导出的 Txt 有什么用？

Txt 里是每一帧的全部函数、FPS 和网格尺寸。可以重新导入本工具再合成一次视频，也可以直接贴到「函数显示器」逐帧查看。

视频会被上传到服务器吗？

不会。采样、生成函数、回放录制全部在浏览器本地完成，断网也能跑。
